# Demo保存、分享与导入：产品讨论

2026-11-03。用户要求纳入设计并听取PM建议；以下除已确认原则外均为候选，不表示已授权实现或已验证跨机器。RUN-005继续完整录制，正式文件管理/分享/导入不扩入该包。

最新方向（D-156至D-158）：历史详情只提供直接播放与收藏demo；独立“管理回放”页先只展示收藏和主动导入的demo，承载导入、播放/导出/改名/移除、文件夹/分类。用户已认可“百科大全→回放管理”，与历史记录同级。普通自动录像从历史记录进入，不默认混入管理页，不在原生历史混入导入录像。收藏只是标签/便捷入口，不代表长期保留或免清理；内部布局/存储/清理/导入保留与移除含义仍待定义。

## 既有要求与当前事实

- 默认自动录制、独立观看且不覆盖普通Continue、同受支持版本环境间文件分享/导入是既有MVP方向；跨版本是后续大型目标，不借导入放开。
- 已结束对局由百科大全→历史记录→左右选局进入；用户已确认观看按钮在原生分享按钮左侧、参照其原生风格、无demo时同样禁用（D-155）。分享按钮目前没有已接通的导出业务。
- 当前开发数据是RunDocument引用多个Clip，Clip包含原生checkpoint/状态/动作等；目录还混有开发session/log/catalog/journal。不能只发送一个root JSON就认定整局包完整，也不应复制整个开发目录作为正式分享。
- 当前存在本地Scope/档案环境校验，尚无正式导入器或跨机器可播放证明。具体必要数据依赖、玩家标识/账户输入如何保持重放语义与最小化导出仍须验证；压缩一个目录不等于完成可移植分享。

## PM建议：保存

- 正常游玩自动增量保存、Continue续写；结束后封存为有明确胜利/死亡/放弃或缺口状态的demo。未完/中断记录保留并明确范围。
- 本地工作存储与原生游戏存档独立、与原生历史真实身份关联；原生历史不当录像数据本体。历史详情负责播放/收藏，管理页负责文件操作，容量/保留策略待定。
- 不把原生历史条目删除自动等同删除demo，反之移除demo也不删游戏战绩。没有demo时观看按钮自然禁用。收藏仅给已存在demo加标签/便捷入口，取消收藏仅移除该标记，不删除录像；不会因点击收藏再复制一份文件。
- 收藏不授予长期保留或免自动清理的承诺，存储/保留/清理规则独立设计，不能从“收藏”反推。PM初期不静默自动清理的建议仍未由用户确认；导入后的存储待遇也另议。

## PM建议：分享

- 对用户导出一个自包含demo文件，包含清单/版本与必要Run/引用战斗/初始化上下文，进行压缩及完整性检查。内部容器/扩展名尚未定，不为了一个文件强制把运行时存储也重写成单文件。
- D-162/D-163：用户已确认先做好自定义卡面，再做PNG demo两个阶段。第二阶段PNG本身承载可导入播放的录像与卡面，不只是普通封面图；技术打包/容量/依赖与跨机器仍待验证。第一阶段不需要先实现PNG容器，卡面字段/模板继续讨论，视觉编辑与真实对局数据分开。两阶段均未派实现，不扩进RUN-005。
- D-164/D-165：DIY包括费用/类型/稀有度/插画/描述等卡牌元素，额外信息用可选盖章表达。有条件的章满足条件后由玩家选择是否盖上，无条件章可直接选；不强制自动印。MVP/弱化专家/连胜/No SL仅举例，具体条件/资格归属/分享携带未定。未来导出需考虑可编辑呈现、可用资格与已盖印章的区别，具体格式未设计。
- 导出在独立管理页进行，输出文件后用户通过已有文件传输渠道分享；首段建议不建上传服务、账号或在线社区。此前借原生历史分享按钮接demo导出的候选撤回；原生分享按钮本身如何处置不在此擅自决定。
- 默认保留所导出录制的完整事实/SL尝试；观看默认最终延续路线，不因简化过程导出就永久丢弃原始事实。是否另提供裁剪/仅单场导出待讨论，不作为首步前置。
- 只包该录像重放必需数据，不附本体DLL、整个账号存档、开发日志/绝对路径。必要的Progress/玩家身份上下文如何处理尚未知，不提前宣称匿名或随意删除重放依赖。
- 2026-11-04 体积实验：只读重组 r22 归档的 139 条路线记录、17 个战斗片共 130 个动作。去掉反复写入的路线/战斗状态、Progress、Prefs 和战前 checkpoint，保留动作与结构元数据，gzip 后约 21 KB；加回现有开局 Progress/Prefs 约 27 KB，再为路线前后与战斗状态加 SHA-256 校验约 37 KB。r22 有录像缺口且没有战斗选择帧，这些仅是负载估算，尚无精简包可播放或随机跳转证明。候选为可移植开局上下文、动作流、校验及少量可恢复的状态或增量；先独立验证同版本从头播放和偏差恢复/定位，再决定 PNG 的实际负载预算。
- 首次打开就能定位是整局导航目标。当前路线 Before/After、战斗 Initial/After 主要用来比对，开局/路线 Progress 会应用到隔离环境；战前原生 checkpoint 可加载，普通局内 Back 使用观看中生成的内存点。旧 STATE-001 仅证明首张防御后的磁盘冷恢复及纠偏。建议 RUN-005 后用一份有多个房间的录像验证：首次打开，直接选后面的未访问战斗动作，从录像内的近邻房间或回合锚点重建，只补算该小段；到达后下一步仍走原生出牌。先记录等待与包体积，再决定锚点密度；选牌窗口仍通过精细前进到达。此为候选验证路径。

## PM建议：导入

- 导入在独立“管理回放”页进行，用户选择demo文件，先读出角色/时间/来源/版本/完整性/可用范围，再入库；不自动开播，不修改普通Continue/进度或把别人的对局写成自己的战绩。
- 原生历史仍只浏览游戏真实战绩，不混入导入录像；自己的收藏/外来录像的文件管理统一在新页组织。用户已确认管理入口在百科大全与历史记录同级。
- D-158管理页成员范围为“有收藏标签，或主动导入”：普通本地自动录像取消收藏后退出管理页，但文件不因此删除，仍能经对应历史记录找到；主动导入文件不要求额外收藏才显示。管理页是否提供来源筛选/去重与文件夹具体操作后续设计，不自动新增全部录像视图。
- 重复导入可提示已存在；新版本/不同内容不得静默覆盖原件。同受支持版本/模组环境才进入正常播放范围，缺内容或格式损坏明确不可用。
- 导入包作为数据处理，验证schema/引用闭合/体积与解包范围后再入受控目录，不从包加载DLL/任意路径/代码。此为该功能所需边界，具体契约与验证在立项时适度制定，不新增当前运行门禁或平台。

## 尚待讨论/验证

独立存储/容量/清理规则、导入文件的保留策略、移除是否删本地文件、文件夹与分类含义、管理页内部布局、文件范围/扩展名、旧片缺依赖提示、真实跨机器与不同档案Scope/玩家身份处理。管理入口、收藏标签与先只显示收藏/主动导入均已确认，不再反复讨论全部自动录像默认进入管理页。文件/UI待另行安排，不默认RUN-005已完成。
