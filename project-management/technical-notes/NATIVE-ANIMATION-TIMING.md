# 原生动画、取消与抽牌时序对Replay的风险

2026-10-27。PM技术补充，非新INV/实施工作包，不改变D-101范围或插入审批。来源分为用户经验、官方历史修复、本地固定版本静态代码与待验证推论。撰写时Implementation同任务修DEMO-005，现已按D-102组合样本收束；本笔记风险未由此复现，不追加旧任务矩阵。

## 用户经验（尚未在本项目复现）

用户约500小时游玩经验：社区有“动画大于一切”的说法；手动拖拽的卡被事件取消后，可能在手牌中换位置；凋萎与带抽牌能力的牌有概率互卡。用户认为这可能影响demo正确性，需要强记录及动画顺序信息。

记录这些为重要现场经验，不将口号升级为所有逻辑依赖所有动画的架构事实。本次公开搜索未找到足以确认“凋萎＋抽牌互卡”同一复现和根因的第一方报告；其精确输入、版本、实际逻辑/显示变化及Task依赖仍未知。不要求用户现在重现，留作后续有价值的时序/纠偏样本。

## 对录制/恢复设计的影响（方向，机制尚待验证）

1. **忠实记录实际发生的结果。** 手动意图、实际接受/提交、取消、完成分开理解；绑定真实牌实例/升级/状态/目标，保留有序逻辑牌堆。若取消本身改变可观察的游戏状态，应记录相应因果事件/权威状态，不能把一张未执行的牌补成成功操作；是否需要保留纯显示排序取决于观看目标，不能默认所有UI移动都是逻辑变化。
2. **保留必要的因果顺序。** 关注会影响输入/效果的抽牌触发、移堆、选择、完成/取消与场景生命周期依赖。时间戳承担节奏，不单独保证异步调度相同。逻辑依赖的Task/信号不能当纯装饰跳过；独立装饰动画可加速，不能又把所有Tween结束当普遍稳定点门槛。
3. **权威状态是数据，不能只有hash。** 现有After投影用于比较，观看期对象memento用于同会话回退；二者均不等于磁盘强记录/跨次恢复。后续STATE增量需要实际落盘可恢复的状态、必要中间/事件边界和安全应用恢复的执行上下文，以覆盖原生bug/时序差异造成的偏差，并记录纠偏来源/结果。不能逐帧复制整场景树以牺牲默认录制性能。
4. **旧异步工作不能破坏已恢复状态。** 状态覆盖后仍在运行的旧动画/回调/订阅须有可说明的归属与清理/重绑定方案；写回HP或牌堆不能保证下一帧不再被旧回调改变。具体手段按路径实现，尚未选择统一架构。
5. **原局不完整仍然是不完整。** 若原游戏已卡死、未到可信完成点且无后续权威状态，强记录也不能生成不存在的后续结果。保留最后可信状态、在途/取消/错误与诊断，明确不完整；只有存在可用真实状态且执行上下文可安全恢复时才纠偏继续。回放不擅自“修正”原局成另一条历史。
