# Replay Mod 测试与备份

更新：2026-10-26，D-092。取代当前开发任务的旧“绝对不变/禁止个人槽读取”限制；旧实验按原条件解释，历史快照见`archive/2026-10-26-before-D092/TEST_PROTOCOL.md`。

## 范围

用户允许先备份，再做较大胆的mod/hook/配置实验，接受开发版失败并手动恢复。原测试Steam账号的unmodded profile1现在允许为备份和必要测试读取/复制，不再是绝对禁区。默认仍使用modded1，其他已授权modded槽也可使用；不无故切换个人槽，另一账号保持排除。

成品“独立Replay不覆盖正常Continue”的目标不变。实验改变测试进度不是自动安全FAIL；若正在测状态等价/隔离，仍按实际差异判断，备份不能代替正确性证明。

## 最小备份流程

1. 确认游戏已正常退出；若仍在运行，请用户退出，不强杀。确定原测试账号，若归属不明只问用户，不遍历其他账号找存档。
2. 将该账号完整本地STS2目录复制到`C:/Projects/STS2ReplayMod-local/backups/<本轮唯一名称>/`：含settings、modded/unmodded存档、profile选择和进度。实际来源依已有存储拓扑/当前账号确认，不凭“1号”猜磁盘路径。可以读取这些内容完成备份，但不把原始payload/账号路径公开到报告。
3. 备份不得覆盖旧备份。确认复制完成、备份可读及关键存档内容校验；记录私有位置、时间和简短恢复说明。只备份/核对需要恢复的文件，不重做数千项旧证据审计。
4. 安装或替换本项目mod前保留已有目标文件；确需修改游戏原文件时另存精确原件。一般Harmony运行时hook不要求先复制整个游戏安装目录。
5. 用户在实际测试前确认Steam Cloud状态；建议关闭以免实验变化同步。不要自动修改Cloud设置或把本地备份宣传为云端备份。备份不包含范围外系统/账号。

同一实验批次可复用明确的恢复点，用户期间有新游玩进度则另作新备份。恢复默认由用户按说明执行；Implementation可在明确本批恢复目标后协助恢复测试状态，但保留失败结果，不用恢复抹掉不利观察。没有实际执行就不得报告“已备份/已恢复”。

## 安装与人工运行

备份后，Implementation可安装/替换本项目DLL/manifest、调整相关mod开关、测试profile和候选模式；写前确定精确目标，游戏关闭时操作，不递归清理宽目录。旧测试mod默认关闭，避免干扰，不为核对开关再要求额外启动一次。

用户请求只需说明：本轮目标、准备条件、具体动作、在哪里停手、预期现象、失败时怎么退出。可将自然相连步骤合成一段，不为每张牌/每次点击等PM审批；真正需要看上一步结果时再分段。达到目标后是否领奖/继续房间必须讲明白。

用户手动启动和操作游戏，不用Computer Use/鼠标键盘自动化，不擅自启动正式STS2或正式headless。可以读取本批日志、测试存档和模组输出排查问题；收集范围与问题相关，不整包公开个人数据。

## 出错后

普通编译、hook、生命周期、UI、计时或observer bug，Implementation可在同任务修复并请求重测。保留重要失败的版本/运行标识和日志即可，不必因一次终态永久退役整个工程；不无意义地新建probe ID/schema。

停止的是有问题的本次运行，不是开发权限。记录不明就写不明，实际效果不等价就写不等价；不能改断言掩盖问题。准备/正常存盘/测量写入分清即可，不为所有任务建立字段级零写入证明。真正测隔离/恢复时另定义最小必要比较。

失败后先查实际源码和当次日志，必要时恢复备份。无法界定写入范围、备份不可用、Cloud/账号风险无法说明或需要改变产品目标时再回PM。正常改代码、备份、安装和可恢复的测试不构成单独审批阶段。
