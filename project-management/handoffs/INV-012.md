# INV-012 — A4 后基线捕获活性与退出写入边界（纯静态）

状态：READY（Project Lead，2026-09-25）

## 目标

在不运行游戏的前提下，解释 `SPIKE-001A4` **可静态确定**的 post-baseline capture/deadline 缺口，并给下一次 reconstruction control 制定可审计的 deadline、telemetry 和保护写入合同。A4 已永久退役；本调查不得把 A4 的无 A/B 结果解释成原生重建差异。

## 固定输入与证据边界

- 先读 `project-management/CURRENT_STATUS.md`、`TEST_PROTOCOL.md`、`investigation-reports/SPIKE-001A4-report.md`、`evidence/spike-001a4/project-lead-final-review.md` 和原 `handoffs/SPIKE-001A4.md`。
- 允许只读 A4 仓库源码、测试、已封存的 A4 baseline/terminal **元数据**、`phase-a-stalled-after-baseline.md`、`post-exit-audit.md`、相关已封存日志，以及固定 v0.111.0 DLL 的 hash-gated IL。`TOOL-001` 外部反编译源码仅用于导航，不得单独作为结论证据。
- 不读取当前游戏存档、replay payload、settings payload、cloud、recovery 内容或其他 profile 的文件；尤其不展开 profile3 数据。不得启动/控制游戏，不用 Computer Use，不安装/启用模组，不修改、构建或运行 A4，也不创建 successor probe。已封存 artifact 不可覆盖。
- 对已封存日志仅抽取必要的 A4 生命周期、时间顺序和写入元数据；不得复制账号 ID、用户目录或无关玩家行为到报告。
- 先读 `project-management/TEST_PROTOCOL.md` 的 2026-09-27 存储拓扑与无头测试增补。本任务仍纯静态；不得把用户关于可能无头工作流的提问解释为启动游戏的授权。

## 要回答的问题

1. 先建立**固定版本的存储拓扑表**：`user://` 实际根、Steam/account/modded/profile1 各层、`settings.save`、`profile.save`、`current_run.save`、`progress.save`、`prefs.save`、backup、`replays/latest.mcr` 的 owner、作用域、生产读取/写入 API、Cloud 边界和正常退出行为。区分逻辑路径、实际磁盘路径与 mod 安装目录，避免把 profile1 所有文件或 account 设置混作一类。只输出路径模板，不输出真实账号 ID；固定 DLL/IL 是正式证据。
2. 从 arm、production-save completion、baseline seal、A readiness 到 A snapshot/terminal，列出 deadline 的所有 start/complete/expiry 及状态转移。用源码与合成测试证明：baseline 后若 readiness 永不满足，旧实现为什么无法在规定时间内终止；新合同如何保证每个等待阶段都有独立、单调计时的上限，且人工等待 `READY` 不触发错误 timeout。包含 race、terminal latch、observer-only exception、process restart 的负向案例。**只设计，不修改 A4。**
3. 审计 ticker `_Process`、readiness predicate、telemetry 存放与 artifact 写入时点。严格区分“原进程确实未 tick”和“原进程 tick 过但数据未落盘”。特别说明后续 resume terminal 中 `totalTicks=0` 的进程身份，禁止把它当作原进程证据。提出最小、非敏感、带界限的原进程 heartbeat/raw rejection 持久证据，使下次即便无 A snapshot 也能区分 ticker、predicate、异常和 deadline；预防无限写盘或正常录制性能外推。
4. 只用固定 DLL/IL 与现有封存元数据，追踪 `replays/latest.mcr` 与 `settings.save` 的 production writer、触发边界和正常退出顺序。特别核对 `NRun` 退出通知、`RunManager.CleanUp/WriteReplay`、`NGame.Quit/SaveSettings`，但不能仅凭导航源码判定A4那次的具体内容差异原因。分别列 Confirmed、Inferred、Unknown；如静态不足，说明需要何种**下一次独立、安全、最小运行观测**。不能事后豁免 A4 的保护失败；不得把 profile3 cleanup 进程写入混为 A4 业务进程写入。
5. 给出下一控制实验的 protection window：A snapshot 前、A 后正常退出、B 启动前各自应比较什么；哪些生产写入可预先按固定契约允许，哪些仍应 fail closed。若必须改变保护集合或允许差异，需单列 Project Lead 决策请求，不得自行改验收门槛。
6. 给出**无头可行性矩阵**：纯 .NET/Mock 测试、独立 Godot `--headless` 工程、正式 STS2 `--headless` 三层分别能验证什么、不能验证什么、需要哪些隔离和用户授权。静态核实 `AutoSlayer` 在v0.111.0 release的入口门禁、是否存在经证实的替代官方CLI测试入口，以及 `--headless` 是否会跳过Steam/SaveManager初始化。不得运行任何一层的新runtime实验；只提出后续最小可行 gate。
