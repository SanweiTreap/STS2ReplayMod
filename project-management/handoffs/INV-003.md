## 任务目标

为 MVP 的“主菜单独立 Replay 会话”选择下一次最小运行实验边界，并评估 RitsuLib 是否能安全减少 Replay Mod 的通用实现工作。

本任务必须回答：在同一个已有正常 `Continue` 的玩家 profile 下，能否从主菜单进入 Replay 管理页并建立一个非进度性 playback run/session，使观看、停止、失败和游戏重启都不修改、替换或消费普通 `current_run.save`；若没有现成完整入口，哪一个且仅一个隔离机制最值得首先验证。

## 产品验收语义

调查必须以以下产品结果为约束，不得用开发工作流替代：

1. 主菜单有专门 Replay 入口，层级与单人/多人游戏并列；设置页快捷入口、暂停菜单按钮或要求先进入一局游戏不满足该要求。
2. 玩家当前 profile 可以已有普通 Continue。
3. 打开 Replay 列表和开始播放不要求创建或切换 profile。
4. Replay fixture/runtime state 不得写入或替换普通 `current_run.save`，不得增加其 reload count。
5. Replay session 不得把观看进度提交为普通 run，不得无意更新普通 run 统计、成就、排行榜、daily 或 cloud payload。
6. 正常停止、加载失败、dispatcher 失败、return-to-menu 和可合理覆盖的异常退出后，普通 Continue 仍保持原位置和内容。
7. Replay 自己的列表、配置、日志和诊断文件可写入明确的 mod-owned 路径；这不等于允许修改游戏进度。

## 调查问题 A：主菜单与 scene 入口

1. v0.111 主菜单中单人/多人按钮、scene 切换、返回路径和 Continue 缓存分别由哪些类型/方法管理？
2. 增加真正并列的 Replay 入口需要注册 API、Godot scene 注入还是 Harmony patch？列出方法体/caller 证据。
3. Replay 管理页能否作为不建立 `RunManager.State` 的普通 UI scene 打开？返回主菜单时需要哪些 teardown？
4. RitsuLib 是否有通用的顶级主菜单页面/按钮注册能力？必须区分：
   - 设置页快捷入口；
   - top-bar button；
   - 任意 runtime UI；
   - 与单人/多人并列的主菜单入口。

符号或 README 中出现“main menu”不足以证明满足产品层级，必须看 API、实现和调用者。

## 调查问题 B：独立 playback run/session

对以下候选逐项追踪方法体、caller、初始化参数和副作用：

- `RunManager.SetUpReplay`
- `NetReplayGameService` / combat replay debug 路径
- `RunManager.InitializeShared` 及其 `shouldSave` 语义
- `RunManager.Launch`、`CleanUp`、`NRun` scene enter/exit
- `SaveManager` / `RunSaveManager` / `ISaveStore` 注入与全局实例生命周期
- profile id provider、current-run path、cloud wrapper
- reload count、run history、stats、achievements、leaderboard、daily 和 game-over/abandon hooks
- normal Continue 的缓存与回到主菜单后的刷新

必须回答：

1. 是否存在 production-usable 的 replay/test/spectate session，能够装载任意 singleplayer Replay 基线而不走 `IncrementNumReloads`？
2. 即使 setup 不直接保存，后续 room/map/combat/game-over/cleanup 中哪些路径仍可能保存或提交进度？
3. `shouldSave=false` 能覆盖哪些 live-run 写入，不能覆盖哪些 direct/side-channel 写入？
4. 是否能在不替换全局普通 save manager 的情况下，为 Replay session 提供 non-persistent 或 mod-owned store？
5. 若必须替换全局 store/context，如何在失败和 teardown 中恢复，哪些状态可能泄漏到普通 Continue？这里只调查，不设计完整实现。
6. 当前普通 run 不在内存、但磁盘上存在 Continue 时，建立 Replay `RunManager.State` 是否可行；返回主菜单后 Continue 是否会从原文件重新读取？
7. 已暂停的 room-before A/B 应成为：
   - 独立 session 实验的一部分；
   - 仅单独的 reconstruction control；
   - 或因无价值而取消。
