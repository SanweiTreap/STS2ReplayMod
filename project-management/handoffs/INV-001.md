# INV-001 Implementation Codex Handoff

状态：Ready  
发出日期：2026-08-26  
后续任务：`SPIKE-001`

## 任务目标

建立一张只服务于 STS2 public-beta `v0.111.0` 最小录制—重放探针的参考地图。调查 RunReplays 和必要的 v0.111 游戏符号，找出候选 hook、已知反例与仍未知项；不设计最终架构，不实现探针。

本任务要降低的唯一不确定性是：`SPIKE-001` 应从哪些具体入口捕获和重新驱动一个最小单人场景，以及哪些 RunReplays 做法不应复制。

- 实验顺序：`project-management/EXPERIMENT_PLAN.md`。

- 目标游戏：public-beta `v0.111.0`，commit `41cef1ea`，`sts2.dll` SHA-256 `0861BFA1DF347538D932F22D580E75420F08082792EB914E53B4882764ACDBE9`。

如本机工具链或目标 DLL 无法只读访问，记录具体阻塞；不要凭旧版本符号补全 v0.111。

## 必须回答的问题

对以下每一类分别给出具体源码文件、类型/方法/patch、调用方向、适用版本和证据等级：

1. 单人 run 的开始、载入、房间进入、楼层/房间结束与 run 结束边界。
2. 最小战斗场景中的玩家语义操作捕获与 replay dispatch；区分 UI 输入、语义命令和游戏 action。
3. 建立确定性最小链路所需的 seed、RNG 状态、初始 run/房间状态及选择结果。
4. 回合、房间、楼层等结构节点如何取得稳定身份和边界。
5. 可用于探针的状态序列化、装载或恢复入口；只报告候选及限制，不提出最终快照方案。
6. 判断下一条语义操作何时可安全执行的 UI/game readiness 候选信号。
7. RunReplays 中位于录制/dispatch 热路径的同步文件 I/O、锁、反射、序列化、全量遍历、日志和 UI 节点查找。
8. 上述入口在 v0.111 中已确认或疑似发生的 API、签名、RNG 或 UI hierarchy break。

## 必须使用的分类

每个条目只能标为以下之一，并解释理由：

- `Confirmed`：由固定源码、目标 DLL 符号或已有运行证据直接支持。
- `Inferred`：证据间接，写明推理链与验证方法。
- `Unknown`：当前证据不足，不得补全。

另为 RunReplays 做法增加用途标签：

- `Candidate hook/concept`：值得在 `SPIKE-001` 中最小验证。
- `Reference only`：可帮助理解，但不应直接移植。
- `Reject for spike`：已知与 v0.111 不兼容、会污染性能结论或超出最小探针范围。

这些标签不是最终“直接复用/重做”架构决策。

## 明确非目标

- 不切换到 v0.107，不重演 RunReplays sample，不继续 D4–I6 历史追问。
- 不修复 RunReplays，不修改其源码或 Workshop artifact。
- 不创建 Replay Mod 正式项目结构，不实现 recorder/player/UI/file format。
- 不研究路线图美术、完整场景覆盖、跨版本、多人、接管或 gameplay mod 协议。
- 不因发现旁支问题而扩大任务；只登记到“仍未知/建议后续”。
- 不把 RunReplays 的整体架构作为建议答案。

## 交付物

使用 `project-management/HANDOFF_TEMPLATE.md` 的证据规范，提交一份 investigation report。报告至少包含：

1. 版本与 artifact 身份核对。
2. 按八类问题组织的模块/符号表。
3. v0.111 break 表：旧符号/做法、目标版本证据、对最小探针的影响。
4. 热路径风险表，明确哪些只是性能假设。
5. 一份 `SPIKE-001` 候选方案：只选一个最小场景，列出建议 hook、最小记录字段、校验状态和失败观测点。
6. 仍未知事项和一个最值得继续验证的阻塞点。

所有本地证据使用可点击的文件/行号或类型/方法名；反编译/符号检查需记录工具、命令和目标 hash。不要只写概括性结论。

## 验收与停止条件

Project Lead 只在以下条件均满足时接受 INV-001：

- 八类入口均有 `Confirmed/Inferred/Unknown` 结果，没有空白类别。
- 每个关键判断可追溯到固定版本证据。
- 至少明确一个适用于 v0.111 的最小捕获入口和一个最小 dispatch 候选，或用证据证明其中之一当前被阻塞。
- 性能风险没有被误写成已证实根因。
- `SPIKE-001` 的范围足够具体，可由另一名 Implementation Codex 独立执行。

满足这些条件后立即停止；不要继续做全面源码导览或实现工作。
